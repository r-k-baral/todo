JS Core 1. Event Loop & Sync vs Async JS
🧠 Samjho (Hinglish):
JS ek baar me ek kaam karti hai (Sync). Agar time lene wala kaam aaye (Async API), toh use browser ko de deti hai. Browser kaam karke result 'Queue' me daalta hai. Event Loop ka kaam hai dekhna ki 'Call Stack' khali hai ya nahi. Khali hote hi wo Queue se task utha kar execute karwa deta hai.
🗣️ Speak in Interview:
"JS is synchronous and single-threaded. For asynchronous tasks, it uses the browser's Web APIs. Once an async task finishes, its callback enters the Task Queue. The Event Loop continuously checks the Call Stack; when empty, it pushes the first task from the Queue into the Stack for execution."

Network 2. What happens when you type a URL?
🧠 Samjho:
1. DNS search karta hai IP ke liye. 2. TCP connection banata hai. 3. Browser HTTP request bhejta hai. 4. Server HTML bhejta hai. 5. Browser HTML aur CSS ko padh kar DOM aur CSSOM banata hai, dono milakar Render Tree banta hai aur screen par paint hota hai.
🗣️ Speak in Interview:
"First, DNS resolution finds the IP. Then, a TCP handshake establishes a connection. The browser sends an HTTP request, and the server returns HTML. The browser parses HTML to build the DOM, parses CSS to build the CSSOM, combines them into a Render Tree, calculates layout (reflow), and paints the pixels."
JS Core 3. Hoisting & Closures
🧠 Samjho:
Hoisting: JS variables aur functions ko run hone se pehle top pe le jata hai. `var` undefined hota hai, `let/const` TDZ me rehte hain.
Closure: Ek function ke andar dusra function. Andar wale function ko bahar wale ke variables humesha yaad rehte hain, chahe bahar wala khatam ho jaye. Data private rakhne ke liye best hai.
🗣️ Speak in Interview:
"Hoisting moves declarations to the top of the scope before execution. `var` is initialized as undefined, while `let` and `const` enter the Temporal Dead Zone.
Closures occur when an inner function remembers the variables of its outer lexical scope even after the outer function has returned. They are used for data privacy and currying."
JS Core 4. Prototypal Inheritance & Deep vs Shallow Copy
🧠 Samjho:
Inheritance: JS me objects ek dusre se properties share karte hain via `__proto__`. Agar object me property na mile, toh wo apne parent (prototype) me dhundta hai.
Shallow Copy: Sirf upar ka data copy hota hai, andar ke nested objects original se jude rehte hain (`...spread`).
Deep Copy: Pura naya object banta hai, koi connection nahi rehta (`structuredClone()` ya `JSON.parse(JSON.stringify)`).
🗣️ Speak in Interview:
"Prototypal Inheritance is how objects inherit properties from other objects via the prototype chain.
A Shallow Copy copies top-level properties, but nested objects share references. A Deep Copy creates a completely independent clone, often achieved via `structuredClone()`."
React 5. React Fiber, Reconciliation & Batching
🧠 Samjho:
Fiber: React 16+ ka engine jo rendering ko pause ya abort kar sakta hai taaki UI freeze na ho.
Reconciliation: React purane Virtual DOM aur naye Virtual DOM ko compare (Diffing) karta hai aur sirf change hue parts ko real DOM me update karta hai.
Batching: Multiple `setState` calls ko React ek sath group karke ek hi baar render karta hai taaki performance bache.
🗣️ Speak in Interview:
"Fiber is React's rendering engine that allows incremental, interruptible rendering to prevent UI jank. Reconciliation is the diffing algorithm comparing the old and new Virtual DOM to selectively update the real DOM. Batching groups multiple state updates into a single re-render cycle for better performance."
React Perf 6. Avoiding Re-renders & Stale Closures
🧠 Samjho:
Re-renders rokne ke liye `React.memo` (component ke liye), `useCallback` (functions ke liye), aur `useMemo` (heavy math ke liye) use karo. State ko niche rakho.
Stale Closure: Agar `useEffect` me state use ki par usko dependency `[]` me nahi daala, toh hook purani value yaad rakhega. Humesha linter warnings ko follow karo!
🗣️ Speak in Interview:
"To avoid re-renders, I colocate state, wrap child components in `React.memo`, and use `useCallback` and `useMemo` to maintain referential equality.
A Stale Closure happens when a hook captures an outdated state variable because it was omitted from the dependency array."
React Perf 7. Memory Leaks & Cleanup (Canceling API)
🧠 Samjho:
Agar component page se hat gaya par uska `setInterval` chalu hai, ya API call pending hai, toh memory leak hota hai. Ise bachane ke liye `useEffect` me return (cleanup) function likho. API rokne ke liye `AbortController` ka use karo.
🗣️ Speak in Interview:
"Memory leaks happen when unmounted components retain active listeners or timers. I prevent this by returning a cleanup function in `useEffect` to clear timeouts and remove event listeners. For ongoing API calls, I use the `AbortController` API to cancel requests if the user navigates away."
React Core 8. Controlled vs Uncontrolled Components
🧠 Samjho:
Controlled: Input ki value React ki state (`useState`) se control hoti hai.
Uncontrolled: Input ki value seedha DOM (HTML) me rehti hai, aur hum `useRef` se jarurat padne pe usko nikalte hain.
🗣️ Speak in Interview:
"In Controlled components, form data is handled by React state, making real-time validation easy. Uncontrolled components keep the data in the DOM itself, accessed via a `ref` only when needed, like on form submit."
Architecture 9. SSR, CSR, SSG, ISR & Hydration
🧠 Samjho:
CSR: Browser me render (slow start). SSR: Server pe render per request (Good SEO). SSG: Build time pe static HTML (Super fast). ISR: SSG ki tarah par background me update hota hai.
Hydration: Server se aayi static HTML par JS lagana taaki button click wagarah kaam karein. Hydration Mismatch tab hota hai jab server aur browser ka data alag ho.
🗣️ Speak in Interview:
"CSR shifts rendering to the client. SSR generates HTML on the server per request. SSG builds HTML at compile time. ISR statically generates pages but revalidates them in the background. Hydration is the process of attaching event listeners to server-rendered HTML. A mismatch occurs if the initial UI rendered by the server differs from what the client expects."
Optimization 10. Code Splitting, Lazy Loading & Bundle Size
🧠 Samjho:
Saari JS ek sath load karoge toh app slow hogi. Code Splitting app ko chote hisso me tod deta hai. Lazy Loading (`React.lazy`) se component tabhi download hota hai jab user us page pe jata hai. Tree Shaking wo process hai jisme unused code bundle se delete kar diya jata hai. In sabse bundle size chota hota hai.
🗣️ Speak in Interview:
"To optimize bundle size, I use Code Splitting and Lazy Loading via `React.lazy` and Suspense to load routes asynchronously. I also rely on bundlers (like Webpack/Vite) for Tree Shaking, which removes dead/unused code from the final bundle."
Optimization 11. Debounce vs Throttle & UI Jank
🧠 Samjho:
Debounce: Type karna rukne ke thodi der baad API call karna (Search bar).
Throttle: Lagatar scroll karne pe har 1 second me API call karna (Scroll events).
Inke bina lagatar API hit hoti hai jisse browser hang hota hai, is lag ko hi UI Jank kehte hain.
🗣️ Speak in Interview:
"Debouncing delays function execution until a pause occurs in the trigger event (great for search inputs). Throttling limits execution to once every X milliseconds (great for scroll events). Failing to use these causes main-thread blocking, leading to UI Jank (frame rate drops)."
Optimization 12. Repaint vs Reflow vs Compositing
🧠 Samjho:
Reflow: Width/Height change karna (Sabse bhari, browser ko sab dobara napna padta hai).
Repaint: Color change karna (Halka).
Compositing: CSS Transform/Opacity change karna (Sabse fast, GPU use hota hai, animations ke liye best).
🗣️ Speak in Interview:
"Reflow calculates layout changes (dimensions, positions) and is very expensive. Repaint updates visual elements like colors without affecting layout. Compositing leverages the GPU to merge visual layers (using `transform` and `opacity`), making it the most performant way to animate."
Optimization 13. Infinite Scrolling & Virtualization
🧠 Samjho:
Agar list me 10,000 items hain, toh sabko DOM me daalne se browser crash ho jayega. Hum 'Intersection Observer' use karte hain API se aur data mangwane ke liye. Aur render karne ke liye 'Windowing' ya 'Virtualization' use karte hain, yani sirf wahi 20 item render karo jo screen pe dikh rahe hain.
🗣️ Speak in Interview:
"I implement infinite scrolling using the Intersection Observer API to fetch the next page of data when the user reaches the bottom. For rendering large lists efficiently, I use Virtualization (like `react-window`), rendering only the items currently visible in the viewport to keep the DOM light."
Security 14. JWT, Tokens Storage & Refresh Flow
🧠 Samjho:
Storage: Access token ko memory me ya `httpOnly` secure cookies me rakhna chahiye. LocalStorage me rakhne se XSS attack ka khatra hota hai.
Refresh: Access token expire hone pe (401 error), Axios interceptor rok leta hai, background me refresh token bhej ke naya access token lata hai aur request dobara bhejta hai.
🗣️ Speak in Interview:
"Tokens should ideally be stored in `httpOnly` secure cookies to prevent XSS attacks. For the refresh flow, I set up an Axios interceptor. If an API returns 401 Unauthorized, the interceptor catches it, pauses the request queue, hits the refresh endpoint with the refresh token, updates the access token, and retries the failed requests."
Security 15. Authentication vs Authorization & CORS
🧠 Samjho:
Authentication: Tu kaun hai? (Login verify karna). Authorization: Tu kya kar sakta hai? (Admin hai ya normal user?).
CORS: Browser ek website se dusri website ke server pe data bhejne se rokta hai. Server headers me permission deta hai, tabhi browser us cross-origin request ko pass hone deta hai.
🗣️ Speak in Interview:
"Authentication verifies a user's identity, while Authorization dictates their permissions (RBAC). CORS (Cross-Origin Resource Sharing) is a mechanism where the server uses HTTP headers to bypass the browser's Same-Origin Policy, allowing a frontend on one domain to request data from another."
Architecture 16. State Management, Service Workers & Caching
🧠 Samjho:
State: Chote apps ke liye Context API, bade apps ke liye Redux Toolkit ya Zustand.
Service Workers: Ye browser aur network ke beech middleman hote hain. Ye files aur API ko cache (save) kar lete hain taaki offline hone pe bhi app chale (PWA). Caching strategies hoti hain jaise 'Cache First' ya 'Network First'.
🗣️ Speak in Interview:
"For state management, I use Context API for localized UI state and Redux Toolkit or Zustand for complex, global server state. Service Workers act as network proxies, allowing us to cache static assets and API responses to enable offline functionality and faster subsequent loads using strategies like Stale-While-Revalidate."
Architecture 17. Race Conditions, API Retries & Bottlenecks
🧠 Samjho:
Race Condition: Agar tumne 'Apple' search kiya fir 'Banana'. 'Apple' ka data late aaya aur screen pe Banana ki jagah dikhne laga. Ise rokne ke liye pichli API ko cancel (AbortController) karna chahiye.
Debugging: Chrome DevTools ka Network tab dekho, React Profiler se check karo kon faltu re-render ho raha hai, aur Lighthouse se score check karo.
🗣️ Speak in Interview:
"A Race Condition occurs when multiple asynchronous requests resolve out of order. I prevent this by ignoring stale responses using boolean flags or aborting previous requests. For handling failures gracefully, I implement exponential backoff for API retries. To debug bottlenecks, I utilize the React Profiler to eliminate wasted renders and Chrome DevTools to analyze network payloads."
